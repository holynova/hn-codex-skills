# 逐站审计记录模板

每站一份，放在审计工作目录的 `<repo>/<repo>.md`。写给人看：下一轮审计、用户审 PR、做前后对比报告时都要靠它。

```markdown
# 审计记录 — #<编号> <仓库名>

- 线上：<线上地址>（部署方式，如 Cloudflare Worker / GitHub Pages / 无线上站）
- 仓库：<owner>/<repo>（默认分支 <main|master>）
- 审计日期：<YYYY-MM-DD>；审计员：<组名>
- 审计分支：`audit-YYYY-MM`，提交 `<完整 hash>`（PR 未合并；默认分支未动，HEAD 仍为 `<hash>`）
- PR：<PR 链接>

## 结论

修 <N> 处，遗留 <N> 项，<有/无>三方案待选。一句话说清本站最大的问题和定型风格是否保留。

## 主链路走查（小白视角）

用一句话写出主链路（入口 → 关键步骤 → 产出），再列走查发现的卡点、讲不明白、衔接不顺的地方。

## 问题清单与修复（按标准编号）

### 标准 1 — 主链路
- **问题一句话。** 修：改法（文件与行号）。

### 标准 2 — 文案
- …

### 标准 3 — 数字/事实（均已读代码核实）
- 每个数字：页面说法、代码/数据源实测、是否一致。

### 标准 4 — 确认弹窗
- …

### 标准 5 — 颜色
- …

### 标准 6 — 字号
- 原 <N> 种（列出）→ 收敛为 4 种：<列表>；grep 验证结果。

### 标准 7 — 字体与符号
- …

### 标准 8 — 设计规范
- …

### 标准 9 — 响应式
- 代码检查结果；是否真机验证（无 live browser 时如实写“未真机验证”）。

没有问题的标准直接省略该节，不要写“无问题”凑数。

## 验证结果

- 构建/语法校验：命令与结果。
- 数字逐项核对：已核对（见标准 3）。
- 字号/符号 grep 验证结果。
- 分支验证：推送成功；推送前后默认分支 HEAD 一致。
- 未做的验证及原因（如未跑完整测试集，因为改动只涉及展示层）。

## 遗留问题

- 逐项列出需要用户决策的事（写清选项与建议），无则写“无”。
- 审计中发现但本次未修的问题也列在这里（如线上图片 404、部署缺口）。
```

## 写作要求

- 每处修复都要有证据：问题在哪看到的、代码里哪一行、改成什么样。
- 数字只写核实过的；没核实到的写“未核实”，不要编。
- 遗留问题必须可执行：写清要用户定什么、选什么、不选会怎样。
