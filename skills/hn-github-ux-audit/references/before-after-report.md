# 前后对比报告制作细则

用户要求“把审计讲清楚”时交付。形式是网页版（静态页），不是 PDF——PDF 只用于三方案机制里的方案挑选。

## 每站 5 项内容

说人话，术语首次出现加括号解释：

1. 违反了什么规则（按十条标准的编号说）
2. 改动方案是什么
3. 改了哪些（逐项，要点式）
4. 前后对比（图或表）
5. 现在的状态（已上线 / PR 待审 / 待重部署 / 待用户决策，附 PR 链接）

顶部加总览：共多少站、修了多少处、按标准分布、状态筛选、锚点导航。

## 对比图

- 左右并排：左改前、右改后；点开放大，放大后能左右切换改前改后。
- 整页截图，宽 390px（手机优先），同一页面、同一范围；改前拍线上旧版，改后拍审计分支本地构建。
- 图注写清差异点与来源；截图里看不到的修复（如对局内逻辑、触屏按钮）在图注里说明。
- 无界面可截的站：
  - 本地工具（扩展、脚本、CLI）：示意还原，按记录里的真实数值绘制并标注“示意”。
  - 跳转页：数值对照表，说明无界面可截的原因。
- 游戏站、长页面：截到 12000px 上限仍截不完时，在图注里写清截断点；核心修复在截断点下方的要注明。
- 大仓库的图片未拉取时，改后图可用线上原图回源，但必须逐站标注。

## 体量与性能

- 30 站以内可做单文件 HTML（图片 base64 内嵌，控制在 15MB 内）。
- 站数多时（95 站约 190 张图会超 40MB）必须做图片独立文件、按需懒加载的网页版；单文件手机打不开。
- 图片压缩到每张 350KB 以内为宜，个别长图超了如实保留。

## 自测清单（交付前逐项过）

- [ ] 章节数与编号齐全，与全局编号一致；“未审的项目”一节存在并说明原因
- [ ] 全部图片加载，0 裂图；无失败请求
- [ ] 390px 与桌面宽度下均无横向滚动
- [ ] 对比图在窄屏下仍为左右并排（或按设计降级为上下，但图注要说明）
- [ ] 灯箱：点开、默认改前、切到改后、Esc 关闭
- [ ] 筛选按状态筛出正确数量；锚点跳转生效
- [ ] 目视抽查至少 3 站截图：页顶总览、改动最大的站、随机一站
- [ ] 导语口径核对：“已发布”只能指线上已生效；只推了代码、未上线或待重部署的要写“已推到 GitHub”，并注明已上线站数
