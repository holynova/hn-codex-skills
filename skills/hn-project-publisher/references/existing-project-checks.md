# 已发布项目：检查与查缺补漏

项目曾上线就使用此入口，包括已有 Cloudflare 发布、只有旧 GitHub Pages 发布，或暂时无法访问的既有站点。不要重走首次发布全流程。延续 SKILL.md 的单一主分支与本地手动部署规则，不创建 Cloudflare 发布分支或 Action。

## 1. 先读现状，不立即修改

核实用户本次要求、Git 状态、远端与唯一主分支、历史发布及实际线上状态，确认是否有待发布的应用变更。复用现有 Worker、域名映射、构建脚本、版本、tracker、README、截图、二维码和作品集条目；不覆盖用户既有修改。

先作检查记录：每项标记「已满足」「需补齐」「不在范围」或「受阻」，附最小必要证据。无法读取账户或线上状态时标为受阻/待核实，不能等同配置缺失而另建资源。已有可靠检查结果且未被本次变更影响时可以复用，不要求每次重新生成材料。

## 2. 按项检查，仅修复实际缺口

| 检查项 | 已满足时 | 缺失、失效或本次变更影响时 |
| --- | --- | --- |
| Git/npm、仓库与主分支 | 复用仓库、历史、依赖及主分支 | 只补必要配置，不重新 init、建仓库或改默认分支 |
| Worker、账户、域名与 Wrangler 配置 | 保留名称、绑定、slug、bindings 与部署命令 | 补缺少的配置或修正错误目标；先核实冲突，不能重复创建 Worker/域名 |
| 生产构建、base、资源与路由 | 复用正常配置；纯检查不强制安装和重建 | 应用变更或部署缺口涉及产物时，运行相关检查、构建、dry-run 与必要预览 |
| 线上 HTTPS、内容与版本 | 核实当前可用内容，无变更时不重部署 | 修复失效环节；源码领先线上且本次要求发布时部署该变更 |
| 页面 Repo 链接与 Umami | 保留有效链接及既有明确 tracker | 只补缺少/错误链接或埋点，不重复注入；尊重统计排除范围 |
| README 与公开链接 | 校验现有文案和链接，不重写全文 | 只修不符合要求、错误/失效链接或本次变更影响的说明 |
| 截图 | 图片存在、视口合适且仍能代表有效页面时复用 | 缺失、加载态/白屏、视口错误或页面变化使截图失实时才重拍 |
| 二维码 | 文件有效且编码最终 Cloudflare Demo 时复用 | 缺失、损坏或编码旧地址时才重新生成 |
| GitHub Homepage | 已与最终 Demo 一致时跳过写入 | 只更新缺失或错误的 Homepage，不为修改元数据重部署应用 |
| xiaosang.cc 收录 | 检查线上条目、截图及 Repo/Demo；正确则跳过 | 查找现有条目并补缺失/错误字段或截图；无条目才新增，不重复收录 |
| GitHub Profile（范围包含时） | 已正确展示则复用 | 只补缺少/错误的项目行、链接或图片 |

具体修复方法按缺口读取 [cloudflare-publishing.md](cloudflare-publishing.md)、[github-publishing.md](github-publishing.md)、[readme-template.md](readme-template.md) 或 [portfolio-updates.md](portfolio-updates.md)，不要求依次执行所有参考里的步骤。

## 3. 决定哪些目标需要发布

- **没有缺口，也没有待发布变更**：报告检查通过，结束。不要自动 bump 版本、制造提交、重拍截图、重生成二维码、重部署项目或作品集。
- **只有 README、二维码或 GitHub 元数据缺口**：仅修改对应材料/元数据。只对真实文件变更提交推送；它们不在部署资产中时不部署项目 Worker。
- **应用代码、线上产物、Worker 配置或部署状态需要修复/更新**：完成关联检查后，仅部署受影响项目。应用变更发版时按既有版本机制递增；恢复配置/域名或重新部署相同产物不为检查强制 bump。
- **只有作品集缺口**：仅修复该条目/截图，检查并提交到作品集 master，再单独部署作品集 Worker；不重新部署项目。
- **作品集仓库已正确、线上内容落后**：从正确 master 提交部署作品集并回读，不重复编辑/提交相同条目。项目本地配置与提交正确但线上落后时同理按发布范围补部署。
- **项目应用更新但作品集信息仍准确**：只发布应用；不因新 deployment ID 自动改作品集日期或重新部署作品集。若截图、简介、链接等确实失实，才同步更新受影响项。
- **仅旧 GitHub Pages 已发布，需迁移 Cloudflare**：保留已有仓库与发布材料，补 Workers 配置、根路径适配、部署与 HTTPS 验证；只更新受迁移影响的 Demo、二维码、Homepage 和作品集条目。无需重做无关初始化、文案、截图或重复收录。

所有写入与部署遵循本次范围和已有授权。检查/审阅请求只报告缺口与具体修复建议，不自行执行外部发布。

## 4. 交付检查结果

报告项目已发布的证据与当前状态，列出已满足并复用的项目、实际补齐内容，以及受阻项。只列实际需要的提交/部署结果。检查确认无需任何修改时明确写「各项已满足，本次无需补齐或重新发布」。
