# 发布时准备中英文 README

## 先看现状

只检查时不修改、不安装依赖。发布需要补齐 README 时才执行下列流程。

- 无 README：创建英文 `README.md`、中文 `README.zh-CN.md`，顶部互链。
- 只有一种语言：保留原文件和主语言，补另一种；沿用已有命名。
- 已有单文件双语：保留，不自动拆分。
- 已有两种语言：仅同步本次变更影响的段落、失效链接或缺项；合格则复用。
- 已有设计、技术说明、许可证、贡献指南：保留。不得为了美化或字数限制删除。
- 通用占位模板且无实质内容：可替换为真实项目说明。全文重设计需用户明确要求。
- 有未提交修改：读取并保留，在现有内容上增量修改；实质冲突无法判断时再询问，不重置文件。

两个版本共享真实截图和二维码；版本、功能、命令、Demo 必须一致。正文和图片说明分别本地化。新简介中文 ≤500 汉字、英文 ≤500 单词，全文不强制截短。

## 美化技能与自动安装

本工作流默认 `auto`：允许缺失时安装以下固定依赖，不自动升级或覆盖已有技能。用户明确指定 `never`（不安装）或 `ask`（安装前询问）时优先遵从。这里是工作流策略，不是 Codex 的自动依赖声明。

1. 先查当前技能目录与已列出的可用技能，按名称发现 `beautify-github-readme`，不绑定某个人的绝对路径。完整可读时直接使用。
2. 缺失时读取可用的 `skill-installer`，使用其安装脚本：

   ```bash
   python3 <installer-dir>/scripts/install-skill-from-github.py --repo oil-oil/beautify-github-readme --path skills/beautify-github-readme --ref e2a8e3898d1ab84c9ea75df68e1ff916b370cbac
   ```

   固定来源为 https://github.com/oil-oil/beautify-github-readme ，包含完整 references/scripts。不得改为搜索同名仓库安装。安装器不可用时不临时执行未知安装命令，直接降级。
3. 已有同名目录不完整、来源冲突或存在用户修改时不覆盖；报告并降级。安装失败最多尝试一次，不循环重试，不改变宿主权限。
4. 安装后读取实际路径的 `SKILL.md` 与当前任务所需资源；不假定当前轮技能列表会刷新。不能读取时使用内置模板。
5. 用户明确要求必须使用美化技能时，无法使用应报告 README 步骤受阻，不把降级结果称为美化完成。

## 调用约定

向美化技能明确传递：

```text
模式：README mode
范围：创建或补齐中英文 README；已有有效内容最小修改
视觉：优先真实截图；必要资产使用静态纯 SVG，不使用 ImageGen/GIF
已有授权：继承本次用户授权的发布范围，由发布技能统一提交和发布
```

模式与实现已经明确时不重复询问。仍需读美化技能的实际指令与所需 references，不能只引用名称就声称使用过。没有必要不创建 hero、装饰、署名；不自动触发 showcase PR。普通发布不等于允许全面重设计。

美化技能不可用时按 `readme-template.md` 完成同样的双语内容要求，报告“内置模板”；可用时按其要求预览并对修改过的 README 运行其 audit 脚本。发布技能负责最终发布，不重复提交或部署。

## 验证与交付

- 对实际 README 文件运行发布校验；双文件传 `--companion`，显式传 `--screenshot`，避免把 SVG hero 当截图。
- `--preserve-length` 保留已有长文档，字数仍输出；单独审阅新简介长度。
- 逐项审阅两种语言的功能、限制、版本、命令和链接是否等价；脚本只能检测基本语言信号。
- 检查图片、二维码内容与真实截图，并预览修改部分。对现有完整 README 不制造提交。
- 交付说明使用美化技能或内置模板，以及创建、更新或复用的文件。仅文档变更且不进入生产资产时，不 bump 应用版本、不部署 Worker。
