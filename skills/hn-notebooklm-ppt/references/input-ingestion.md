# 多模态素材预处理与 NotebookLM 来源分片规范

把任意形态的原始素材转化为 NotebookLM 最容易准确理解、最少产生幻觉且高概率生成成功的结构化 Source。

---

## 1. 核心原则：一源一 PPT 与防幻觉边界

1. **一源一 PPT（1 Source = 1 Deck）**：
   - 每个成品幻灯片只对应一个独立、边界清晰的 Source，并在 `nlm slides create` 时显式传入 `--source-ids <source_id>`。
   - 切忌把几十篇文章或长合集塞成单一大文件，也不要不传 `--source-ids` 让模型在整本笔记中自由拼接。
2. **结构化纯文本头部护栏**：
   - 上传本地整理后的文本源时，在正文前写入极简元信息与边界指令，提前封堵模型常见幻觉：

   ```text
   标题：<清晰标题>
   来源：<节目/作者/出处>
   日期：<YYYY-MM-DD>
   原链接：<公开URL，可选>
   说明：以下仅是这一主题的原始素材（若含语音识别误差请谨慎辨识）。不要把片头混剪、广告口播或跨期预告当成主体内容；不要猜测文中未出现的年份、数字、集号或引语。

   [00:00:12] 正文第一段……
   [00:01:45] 正文第二段……
   ```

3. **前置降噪清单**：
   - **去广告与片头混剪**：播客、视频开头常有往期高能混剪或赞助商口播，需尽量剥离或标注，避免 NotebookLM 把片头口播当成开篇核心人物。
   - **ASR 同音错字谨慎修正**：对明显的专有名词语音识别错字可在源文本阶段或后置校对修正；无法核实的人名、年份、金额宁可保留原表述并在补充说明中注明，绝不脑补。
   - **隐私与仓库隔离**：原始逐字稿或本地未清洗文件统一放在 `.gitignore` 忽略的 `work/` 目录下，计算 `source_sha256` 追踪变更，严禁把原始逐字稿打包进公开网站目录 `dist/` 或提交至公开 Git 仓库。

## 2. 多模态输入转换路线

根据输入源类型选择最稳妥的转换路径：

| 输入类型 | 首选入库方式 | 降级 / 清洗策略 | 关键注意 |
| --- | --- | --- | --- |
| **长文章 / Markdown / 技术文档** | 清洗多余导航/页脚后保存为 `.md` 或 `.txt`，`nlm source add <nb> --file ... --title "<id>｜<title>" --wait --json` | 若单文档超过数万字或包含多个独立议题，按章/节拆成多个独立 Source | 保留真实小标题层级，去除无关侧边栏、评论区和 HTML 标签垃圾 |
| **网页文章 / 在线文档** | `nlm source add <nb> --url <url> --wait --json` | 若遇到登录墙、JS 渲染空白或抓取了大量页面推荐链接，先本地提取正文纯文本再走 `--file` | 入库后建议抽检或先用 `notebook query` 确认正文完整抓取 |
| **YouTube 等公开视频** | `nlm source add <nb> --url "<youtube_url>" --wait --json` | 若视频无内置字幕、语言不对或需精确时间戳校验，先用工具（如 `yt-dlp --write-auto-subs` 或转录）生成带时间戳文本走 `--file` | 多分P长视频或播客录像按单集拆成独立 URL 或独立时间戳文本 |
| **本地视频 / 播客音频** | 提取字幕（SRT/VTT）或用本地 ASR（如 Whisper / FunASR）转录为分段 JSON/文本，格式化为 `[HH:MM:SS] 文本` 后 `--file` 上传 | 口语过于碎片的段落可按 20–60 秒或说话人轮次合并分段，保留起止时间戳 | 保留毫秒换算后的 `[HH:MM:SS]` 时间戳，既方便后续文章章节锚点校验，也帮助 PPT 梳理时间线 |
| **PDF 论文 / 报告** | 原生文本型 PDF 可直接 `nlm source add --file <pdf>`；若多栏/扫描件排版混乱，先做版面还原提取为结构化 Markdown | 多篇合订 PDF 先按单篇拆分，避免整本合集混合提问 | 确认文本可提取，避免纯图片扫描件导致来源内容空洞 |

### 唯一 Title 前缀约定

在上传 Source 时，强烈建议在 `--title` 加上唯一稳定 ID 前缀（如 `<item_id>｜<展示标题>`）：
- 上传前先运行 `nlm source list <notebook_id> --json`，匹配 `title.startswith("<item_id>｜")` 实现**幂等复用**，防止网络超时后重复上传同一份素材。
- 注意在生成幻灯片的 `--focus` 中补一句「不要把文件名或标识符写进标题」，防止内部 ID 泄露到封面文字中。

## 3. 笔记本容量硬护栏（≤ 50 来源 / 本）

在长期批量生产中观察到一个决定性的可靠性边界：

- **禁止单本膨胀**：当一个 NotebookLM 笔记本积累过多来源或超过 **80–100 个 Studio 产物**时，状态查询变慢、上下文干扰加重，且 `slides create` 极易触发**无明确报错原因的服务端静默失败（`status=4`）**。
- **硬上限：每个笔记本最多 50 个来源（`<= 50`）**。

### 推荐分片与固化模式

1. **专题聚合本**：同一系列或强关联主题（如“专题A 5集”、“产品手册 12章”）放入同一个笔记本 `项目名｜<专题名>`，方便同主题上下文核查与复用。
2. **零散内容分桶本**：不属于固定系列的零散单篇/单集，按每桶上限 50 条切分为 `项目名｜单集组1`、`项目名｜单集组2`……
3. **分桶映射持久化**：
   - 将每个条目的 `standalone_group`（桶编号）持久化到固定队列清单（如 `state/queue.json`）。
   - 后续有新内容加入目录时，**旧条目沿用已落盘的组号**，新条目只往当前未满 50 条的最高组号或新建下一组追加——绝不因为重排序而把已入库的条目挤到别的笔记本里。

## 4. 入库与上传命令模式

```bash
# 1. 查找或创建笔记本（先 list 再按精确标题匹配，避免重复创建）
nlm notebook list --json
nlm notebook create "项目名｜专题或单集组1" --json

# 2. 检查是否已存在同前缀来源
nlm source list <notebook_id> --json

# 3. 上传结构化文本源并等待索引完成（建议超时放宽到 ~660s）
nlm source add <notebook_id> --file work/<item_id>.txt --title "<item_id>｜<可读标题>" --wait --json

# 4. 或直接添加公开网页 / YouTube URL
nlm source add <notebook_id> --url "<url>" --wait --json
```

> 所有写操作（`notebook create`、`source add`）都应先在本地状态写入 `pending_notebook` / `source_status='uploading'` 检查点，并禁用 `nlm` 的内部自动重试。详见 [references/nlm-resilience-pipeline.md](nlm-resilience-pipeline.md)。
