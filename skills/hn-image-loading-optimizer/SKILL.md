# HN 图片加载优化

把图片链路拆成「列表先轻量可见 → 当前详情按需高清 → 下载/导出才取原图」，同时控制请求、解码、DOM 和布局成本。来自 rubber-stamp 的代码经验，适配目标项目，不要求照搬目录、参数或框架。

## 工作方式

- 用户要求分析/检查时，交付有源码与网络证据的发现；要求修复/优化时才修改目标项目。此技能不负责发布，不自动改域名、分支、Action 或作品集。
- 新图片系统设计完整链路；已有系统先核实配置与实测，复用有效优化，只补缺口。保护原图、已有分类/元数据、文件路径与导出质量。
- 阅读 [references/rubber-stamp-study.md](references/rubber-stamp-study.md) 了解全部来源技巧及代码局限。来源已实现、可复用经验与额外建议必须分别说明，不能把注释中的效果数字当实测。

## 1. 盘点与基线

找出图片来源/数量、尺寸/字节、可见卡片宽度和 DPR、列表/详情/分享/导出各自 URL、衍生资产脚本、加载属性、状态与缓存。沿调用路径追踪，不能仅靠搜索到 lazy/decode 就判定通过。

在相同视口、节流、缓存状态和操作下记录首屏请求/图片字节、DOM 数、FCP/LCP/CLS、详情出图时间与快速翻页表现。验证方法见 [references/verification.md](references/verification.md)。只有源码时明确没有浏览器/网络实测。

## 2. 建立三层资产

| 用途 | 资源 | 请求时机 |
| --- | --- | --- |
| 列表与分享预览 | 缩略图 | 首屏必要图片优先，其余接近视口加载 |
| 当前详情 | 高清压缩图 | 用户打开或切到该项后后台加载 |
| 下载、打印与高质量导出 | 原图 | 用户明确触发时加载 |

- 保留原图，构建时生成 WebP/目标支持的压缩格式，不让浏览器运行时给每张原图缩图。rubber-stamp 的起点是缩略宽 400、quality 82，详情 quality 85；按目标显示尺寸/DPR与视觉比较调整，不把这些值当普适最优值。
- 小源图不放大；详情是否缩尺寸由实际展示需求决定。源案例详情仅转 WebP，没有 resize。混合宽高比使用真实 dimensions，而不是一律填 400×500。
- 用明确的 thumbnail/detail/original 元数据或可靠路径映射，保留子目录与扩展名；核实每个衍生文件存在。原图替换后更新衍生资源及缓存版本。已有 fingerprint/CDN 缓存机制优先，不无依据新增 Service Worker。
- 大批处理限并发，排除衍生目录、备份与无关素材；增量生成同时考虑源内容/时间与编码参数，避免仅凭文件存在跳过过期图。数据重建保留已有分类与字段。

## 3. 列表加载与渲染

- 仅首屏实际需要、可能成为 LCP 的少量图片 eager/high；其余用 `loading="lazy"`，按需 `decoding="async"`。不要全部懒加载或全部 high。
- 小批初始化、滚动哨兵追加；重用已有分页/框架机制，断开旧 observer，过滤/分类切换后正确重置计数。提供不支持 IntersectionObserver 的「加载更多」等可达回退。
- native lazy 控制图片请求，分批渲染控制 DOM，`content-visibility: auto` 控制离屏渲染成本，它们不是相互替代的方案。仅追加 DOM 不叫虚拟列表；量级需要时再做窗口化。
- 用真实 width/height 或稳定 aspect-ratio 预留位置；容器、缩略图、详情图的裁切保持一致。加载态可骨架占位/淡入，成功停止动画，失败有稳定状态，尊重减少动态效果设置。
- 搜索防抖、避免重复重建同一分类与整页重渲染；参数依据交互与实测调整。

## 4. 详情渐进升级与预取

- 先显示该项缩略图，离屏 `Image` 加载详情图并等待 `decode()` 成功，再更新可见图。加载/解码失败时保留已可见缩略图，避免先清空再等高清图。
- 每次切换递增 request token，并核对当前 item；关闭、卸载或列表切换也使 token 失效。迟到的结果不得覆盖新项。token 只丢弃结果，不表示取消下载。
- `decode` 不可用时在设 src 前安装 load/error handler，兼容缓存已加载状态。回退有明确顺序与次数；详情失败是否允许下载原图由流量预算决定，不盲目重试。
- 只预取相邻少量缩略图，避免连续翻页引起多张 MB 原图下载。相同 URL 可利用浏览器 HTTP 缓存，但不把 new Image 当成自建缓存；应用缓存如需要应有容量与生命周期。
- 稳定视口可复用前/当前/后三个 slide，并用 transform 做移动，不把整个图片集塞进轮播。只给必要元素使用 will-change。

适配原生 DOM 项目时可复用 [assets/progressive-image.mjs](assets/progressive-image.mjs)。它是针对源代码竞态/失败问题改进的参考，不是上游原始实现。React/Vue 等用各自生命周期实现同样约束，不叠加第二套控制器。用法与取舍见 [references/implementation.md](references/implementation.md)。

## 5. 下载、分享与依赖

分享弹窗先用缩略图，生成高质量卡片/下载原图时才请求大图；等待图片与字体就绪，核实 CORS。成功生成文件后释放 Object URL，注意不能过早释放导致下载失效。分享体验细节可复用已安装的 hn-share-card；缺少该技能时直接按项目实现，不把它变成必要依赖。

批量导出使用串行或有界并发、进度与取消/失败状态，控制原图与 ZIP 在内存中的峰值；串行下载仍会把文件留在 ZIP 内存，不能声称恒定内存。二维码、ZIP 等大依赖真正按需加载并复用 Promise，失败后允许重试，检查 HTML 中是否仍有 eager script。

## 6. 验证与交付

按 [references/verification.md](references/verification.md) 检查冷/热缓存、首屏、长滚动、搜索/分类、快速翻页、关闭重开、图层失败及导出。只报告实测结果，不承诺「无感」「98%」等固定收益。

交付：发现与源码位置、修改/复用项、三层图片路径和参数、前后同条件指标、实际浏览器验证、未验证/受阻项。提供流量与画质取舍。只有分析请求时不把建议写成已实现。
