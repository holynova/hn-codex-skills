# 项目开场

先用几句话说明你理解的目标、这次要交付什么、用户会怎样判断它做成了。区分用户想取得的结果和用户提出的做法；遇到尚未确定的验收标准，把你的建议标明为建议。

结合已有对话和能查到的项目事实判断哪里仍有歧义。如果不同答案会改变目标、范围或验收方式，直接问用户，并说明答案会改变哪项决定。优先问最能消除分歧的问题。用户只输入技能名时，先请对方描述项目想法。

检查方案赖以成立的假设。发现要求互相冲突、做法难以达到目标，或有明显更简单的办法时，点明具体假设、依据和后果，给出一个可行的替代做法或验证办法。没有实质异议时直接推进，无需凑问题。

只暂停依赖用户决定的部分。需求已经清楚时，复述后继续完成用户本次要求的工作；用户只想讨论或明确要求先确认时，停在约定的阶段。同一项目的后续对话沿用已确认的结论。
