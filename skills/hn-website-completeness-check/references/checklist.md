# 网站完整度检查表

每项填写通过、缺失/失效、待验证或不适用，并附实际文件/DOM/URL证据。默认五项必检；扩展项按项目需要，不从建议推导额外开发范围。

## 识别与公开说明

| 项目 | 检查与通过条件 | 注意 |
| --- | --- | --- |
| favicon（必检） | head/framework metadata 中引用真实资源，最终 URL 可加载且可辨识 | 空 data:,、未用的 icon 文件、200 HTML 或错误 MIME 不算；子路径/Cloudflare根路径需正确 |
| icon/logo（必检） | 标识有设计意图，和项目名/用途一致，实际展示且小尺寸可读 | 可用字标/单字印记；与 favicon 可同源，但分别验证用途；不要求每个网页有完整品牌手册 |
| 页面 Repo 链接（必检） | 页头/页尾/关于区可见，指向当前仓库且移动端能访问 | 作者 Profile、其他仓库、注释里的链接不满足项目 Repo 要求 |
| GitHub About（必检） | description 是当前项目一句话简介，Homepage 是实际生产入口 | 检查 GitHub 元数据，package.json 不能替代；发现过时旧名/域名时指出 |
| README（必检） | 说明谁用/解决什么、真实功能、在线体验、Repo、真实截图、当前运行/构建方法 | 有文件不等于合理；不要求固定模板/字数，项目沿用publisher约定时检查双语≤500和二维码 |
| 内容与版本一致 | 名称、数量、功能、页面、README、仓库介绍与当前代码相符 | 不沿用旧截图/不存在功能；工具成熟度/限制说明以事实为准 |
| 截图/预览 | 真实有效内容、对应当前版本、合适视口、仓库内可访问 | loading/白屏、移动页桌面拉伸、破图失效均需补齐 |
| 来源/许可/归属 | 数据与素材来源、作者/许可证按项目已有要求可追溯 | 不凭想象补授权；用户未要求时不为检查更换许可证 |

## 分享与传播

| 项目 | 检查与通过条件 | 适用范围 |
| --- | --- | --- |
| 图片分享卡片（必检） | 可见入口、真实内容、项目标识、二维码/可读URL、预览与下载/分享操作 | 内容站网站级；工具/画廊可结果级；既有正确实现复用 |
| 深链接/状态还原 | 打开分享URL能定位目标内容，刷新/前进后退正常 | 有详情、筛选或结果状态时；不要往URL写私密输入 |
| 二维码 | 真正解码为正确 HTTPS 地址，并访问验证目标 | 卡片与发布README已有/要求时；图片存在不等于正确 |
| 分享失败/回退 | 生成loading/error、取消恢复、Clipboard失败可手动复制，native不可用可下载 | 无系统分享API不应整个功能失效，不实际发送给第三方 |
| Open Graph | 初始生产HTML中有合理title/type/url/image，图片绝对地址可达且内容对应 | OG是链接预览，与图片下载卡分开检查；只JS注入可能不被平台抓取 |
| 社交预览补充 | 所需平台的description、image尺寸/alt等合理，无localhost/旧Pages | 平台真实抓取不可用时标待验证，不因无meta标签宣称平台实测失败 |

## 页面基础与使用体验

| 项目 | 检查与通过条件 | 适用范围 |
| --- | --- | --- |
| HTML元信息 | 非模板title、有效description、lang与viewport | 所有网页 |
| canonical/链接 | canonical存在时对应真实生产路径，无localhost或误指另页 | 搜索可索引内容站更重要；工具/PWA按需要，不凭缺失阻断 |
| 移动端 | 375–430px可阅读操作，无横向溢出，按钮不被固定栏遮挡 | 所有面向公众网页 |
| 可访问交互 | 表单有标签、按钮有名称、键盘焦点清楚、弹窗可关闭/合理管理焦点、图片有适当alt | 以实际控件为准；装饰图可空alt |
| 初始/加载/空/错误/成功 | 核心操作各状态可理解，有等待反馈和错误恢复，不永久loading | 有数据/网络/生成操作时 |
| 核心路径 | 一次完整主要任务可完成，输入校验、重试、复制/下载可靠 | 工具/游戏/互动站；静态内容核心是阅读与导航 |
| 404/坏链接 | 实际不存在页面有明确结果/导航回退，内外链接不误跳 | 有路由的网站，SPA资源200 HTML也需检测 |
| 布局/排版 | 信息层级、字号、对比、间距、长文案/长标题与窄屏合理 | 只报告具体问题，不借完整度检查全面重设计 |
| 可选主题/PWA | 已宣称支持的主题/安装/离线确实可用 | 未承诺时不要求开发，不把缺manifest当普通站缺陷 |

## 图片、性能与发布一致性

| 项目 | 检查与通过条件 | 适用范围 |
| --- | --- | --- |
| 图片资源 | 大量图片使用合理缩略层/详情层，必要首屏优先，后续lazy，尺寸占位与失败回退 | 图库、目录、作品集；需要时转图片优化技能 |
| 初始负载 | 非必要大库/原图不在首屏全量请求，重复脚本/请求受控 | 有实际性能问题的页面；不强制改所有依赖 |
| HTTPS/资源路径 | 生产页、JS/CSS/图标/图片成功，版本内容是预期部署 | 本地和线上分别记状态，保留证书验证 |
| Demo一致性 | README、二维码、GitHub Homepage、卡片、作品集指向同一已核实生产URL | 个人完整发布约定；保留明确镜像/历史例外，不批量改其他项目 |
| 作品集收录 | 线上条目有正确简介、截图、Repo/Demo，源数据和线上一致 | 用户要求或个人发布范围内；非个人项目不适用 |
| 来源与部署 | 一个主分支维护源码/配置，Cloudflare本地手动发布，无专用发布分支或新增Action | HN个人发布约定；检查不等于执行迁移或删除历史分支 |
| 统计 | 既有/要求的tracker一次加载、域名过滤正确，基本动作有可验证请求 | 用户约定需要时，明确不要求统计则不算缺口；不在审阅中新增埋点 |
| 基本项目卫生 | 不引用本机路径/测试域名，不暴露配置中的秘密，部署产物排除生成备份与源文件 | 实际存在问题才报告，不扩展成通用安全/合规审计 |

优先级按具体影响：坏入口/失败核心功能为阻断，用户五项的有效性缺口通常重要；纯元数据增强与可选体验可作为优化。不能因favicon缺失就说应用不能运行，也不能因功能可用就忽略品牌与传播缺口。
