# HN 网站完整度检查

判断项目是否「可识别、可理解、可使用、可分享、可维护」，输出有证据的缺口与最小补齐方案，不把每个个人项目变成同一套产品。

## 范围与入口

- 用户说检查/审阅：只读项目、仓库元数据、构建产物与页面，给出发现；要求检查并修复/补齐：只修实际缺口。不要因检查自行推送、部署、发布分享内容或新增统计。
- 先辨别项目类型（工具、内容站、画廊、游戏、作品集）与首次发布/已发布状态。已有项目复用正确资源与配置，不重新初始化、重做 README、重复生成图标或完整发布。
- 每项使用「通过／缺失或失效／待验证／不适用」；不适用给理由。文件/关键词存在、功能可用和线上验证分别记载；工具缺失或权限不足用待验证，不冒充通过。
- 读取 [references/checklist.md](references/checklist.md)。用户指定五项必检，其他项按产品和本次范围评估。项目类型会影响优先级，缺少可选 PWA、主题、账号/后台等不自动算缺陷。

## 1. 识别实际项目与站点

核实 cwd、Git 状态、remote、默认主分支、package/lockfile、框架入口/根布局、资源目录、生产域名、部署方式与 README。跟踪真实使用的文件，不审错历史 HTML、未引用模块或旧输出。

核实 GitHub repository 的 description、Homepage、README 与实际 URL，不把 package.json 的 description 当成 GitHub About，也不把个人 Profile 链接当成项目 Repo 链接。站点无公共仓库或明确不公开时说明限制，不擅自改变可见性。

有本地与线上环境时分别记录版本/提交和检查对象；本地配置正确不能证明线上已更新。页面暂时失效不等于从未发布。

## 2. 五项必检

| 项目 | 要证明的内容 |
| --- | --- |
| favicon | 页面正确引用真实可辨识资源，路径/格式与部署一致，浏览器标签有效；空 data:,、404 或返回 HTML 不算通过 |
| 页面 GitHub 链接 | 正常界面可见且可达，指向实际项目仓库，不是仅藏在代码或指向作者 Profile |
| README 与项目介绍 | 仓库 About 有有意义简介；README 说明项目用途、真实特性、在线体验、有效截图与可执行运行方式，内容与当前产品一致 |
| 分享卡片 | 网站级或结果级入口适合产品；有真实内容、项目标识、可用链接/二维码、下载或分享回退，打开链接能还原目标页面 |
| icon/logo | 有有意设计且符合项目的标识，实际用于页面/资产；设计过的字标可以成立，普通 GitHub 图标或空占位不等同项目品牌 |

不能用 favicon 代替 logo 检查，也不能用 OG 标签或复制链接按钮代替用户要求的图片分享卡片；这些分别报告。纯内容网站可采用网站级介绍卡，工具/画廊可按真实结果提供结果级卡，不强制同时实现两种。

## 3. 按项目补充检查

核实 title/description/lang/viewport、canonical 与 Open Graph 分享预览；手机布局、键盘和对话框、加载/空/错误/成功状态、结果深链接及返回行为；必要的复制/下载；图片性能与缓存；README/二维码/Homepage/作品集 Demo 的生产 URL 一致性。详细通过条件和适用场景见检查表。

公开个人项目范围内检查作品集收录与统一 Umami 约定；其他项目仅按既有要求检查，缺少统计不自动阻断发布。许可证/归属、数据来源/更新时间等以已有事实与项目需要检查，不猜测授权或新增法律承诺。

## 4. 最小真实验证

阅读 [references/verification.md](references/verification.md)，在可用环境检查实际渲染、资源响应、桌面与375–430px移动端、一次核心操作和一次分享/下载（存在时）。二维码需要解码/扫码后确认目标；不要只看文件名。分享检查生成/预览/下载或系统弹窗回退即可，不发送给第三方。

源码搜索可缩小范围，不能单独证明功能通过。API/后台/线上不可访问时完成独立可做项并列待验证，不能为一个失败步骤无限重试。

## 5. 报告与按需补齐

每个发现写清楚检查对象、证据路径/URL、用户影响、优先级与最小修复。阻断项是入口/核心操作不可用、错误指向或失败循环；品牌、说明和分享缺口通常重要；可选体验通常优化项，不机械计分。

需要修复时按缺口复用可用技能，不重复做检查与访谈：

- favicon/icon/logo/截图：hn-visual-asset-pipeline。
- 图片分享卡片：hn-share-card。
- 图片密集列表：hn-image-loading-optimizer。
- 布局排版与工具交互：hn-ui-layout-typography-audit、hn-tool-ui-polisher。
- 用户要求统计：hn-web-analytics；要求发布/作品集补齐：hn-project-publisher。

这些是可选路由，未安装时按当前项目直接处理，不依赖它们才能完成检查。**沿用每个仓库唯一主分支；不为检查/Cloudflare 发布新建发布分支或 Action。** 发布只在已授权范围内进行；已发布项目只补必要目标。

```text
检查对象：项目/分支/提交，本地或线上 URL，模式：只检查/检查并补齐
五项必检：各项状态 + 证据
其他适用项：状态 + 优先级
实际修复：修改与复用项（仅修复模式）
验证：页面/资源/分享/移动端/项目检查
待完成：未验证项、阻断原因与具体下一步
```

无缺口则说明检查通过，不制造提交、版本升级或重部署。案例提炼见 [references/project-lessons.md](references/project-lessons.md)，来源项目仅作参照，不视为全部检查已合格的模板。
