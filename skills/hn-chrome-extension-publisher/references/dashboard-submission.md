# Dashboard Submission

Enter this phase only after local materials pass and the user explicitly authorizes dashboard work.

## Authorization Prompt

Check existing explicit authorization against the actions below. Ask only about uncovered actions, after presenting the concrete publisher/item, version, and package; do not ask again for unchanged scope:

- opening the Chrome Web Store Developer Dashboard in the user's authenticated browser
- selecting the publisher and item
- creating a new item or uploading a new package
- filling store listing, privacy, and distribution fields
- uploading icons, screenshots, and promotional images
- clicking `Submit for review`

Local material preparation does not authorize dashboard access or upload. If the user explicitly authorizes dashboard filling and upload but not final submission, perform only those actions, save the draft, and stop before `Submit for review`. Continue independent authorized work while any remaining approval is pending; silence and tool failure are not consent.

## Computer Use

- Load the available Computer Use or Chrome-control skill before operating the UI.
- Reuse the user's existing logged-in session; never ask for passwords or export cookies.
- Confirm the publisher account, extension name/item ID, current published version, visibility, and target channel before changing anything.
- Upload only the verified package and assets from the reported release paths.
- Use the prepared canonical text; do not improvise policy answers in the dashboard.
- Let the user complete CAPTCHA, two-step verification, registration fees, payment, and attestations requiring personal judgment.
- Treat warnings about permissions, privacy, remote code, distribution, or policy as blockers until resolved.

## Final Review

Before submission, compare the dashboard against the package and prepared materials:

- name, description, version, and item identity
- screenshots and promotional images
- website, support, and live privacy-policy URLs
- single purpose and every permission justification
- remote-code and user-data declarations
- countries, visibility, trusted testers, and rollout/publish timing

Click `Submit for review` only if explicitly authorized. Capture the resulting status and report whether automatic publishing or deferred publishing is selected. Do not claim publication while the item is only uploaded, drafted, or under review.
