# HN 网站分享卡片

## 目标

把网站已经产出的成果变成一张可传播、可回到原页面的图片卡片。默认支持两种入口：

- **结果级**：用户在某条结果、词条、分析报告或生成物旁点击分享，卡片包含该结果和指向详情页的二维码。
- **网站级**：用户在首页或关于区分享整个项目，卡片包含项目介绍、站点 URL 和二维码。

优先复用现有项目中的 `ShareCardButton`、`brand-share`、Canvas 渲染、颜色变量和事件埋点，不要另起一套与产品视觉割裂的分享系统。详细数据契约和 Canvas/系统分享实现见 [references/share-card-implementation.md](references/share-card-implementation.md)。

## 工作流

### 1. 盘点页面与既有实现

先检查项目的框架、结果数据模型、稳定详情 URL、logo/字体/颜色、是否已有分享卡片，以及当前部署的 base path。搜索 `ShareCardButton`、`share-card`、`canvas.toBlob`、`navigator.share`、`QRCode` 等现有代码；能提取为通用函数就不要复制粘贴。

确认分享范围：结果级或网站级；确认二维码打开的 URL；确认是否允许把当前筛选、语言或排序编码进 URL。默认只分享公开结果，私密内容、原始搜索词、用户输入和大段未验证文本不得自动进入二维码或图片。

### 2. 固定分享数据契约

先从真实数据模型构造一个小而稳定的 `ShareCardPayload`，至少包括 `scope`、`title`、`description`、`result`、`url`、`qrUrl`、`brand` 和可选 `logoUrl`。结果字段可以是短摘要、标签、来源、数值和日期，但不应把整页 DOM 或未经整理的对象直接塞进渲染器。

`url` 用于复制和页面链接，`qrUrl` 用于二维码；长结果不要放进 query string。优先使用已有详情页、稳定 slug 或公开结果 ID；只有无敏感、短小且可复现的参数才放入 URL。二维码 URL 可追加 `utm_source=share_card&utm_medium=qr`，但必须保留可读的目标路径并避免泄露用户输入。

### 3. 设计卡片信息层级

一张卡片至少要让未打开网页的人看懂“这是什么、结果是什么、去哪里查看完整内容”：

1. 项目名或小标识。
2. 结果标题和最关键的 1–3 个结论/字段。
3. 一句项目介绍或方法说明。
4. 必要的日期、标签、来源或状态；争议/待核实内容必须保留原有状态标记。
5. 二维码、短提示和完整页面地址的可读 fallback。

默认设计为高分辨率竖卡（例如宽 1080 px、动态高度），移动端预览按容器缩放；保持较大的正文、足够对比度和安全边距，不把所有字段硬塞进一张图。

### 4. 实现打开、生成和分享

点击分享按钮后打开 `<dialog>` 或项目现有 modal，显示生成状态；生成完成后显示图片预览和以下操作：

- **下载 PNG**：`canvas.toBlob()` 生成 `File`，点击下载锚点后再延迟释放 Object URL。
- **系统分享**：先检测 `navigator.share` 和 `navigator.canShare({ files: [file] })`，支持图片文件时分享图片、标题、文字和 URL；不支持时回退到下载/复制链接。
- **复制链接**：使用 Clipboard API；失败时把可复制的 URL 展示在状态区或输入框中。

使用 `aria-live` 提示“正在生成、已生成、已下载、已取消或失败”；关闭按钮、Esc、点击 backdrop 和移动端滚动都要可用。二维码和图片生成失败时仍保留复制链接，不让分享入口变成死按钮。

### 5. 保证图片可重现

优先使用 Canvas 直接绘制文本、分隔线、色块和二维码；复杂视觉可以使用经过审查的 DOM-to-image 方案，但要处理字体、跨域图片、SVG、阴影和滤镜的兼容性。生成前等待 `document.fonts.ready`，图片使用同源资源或正确的 CORS 头，并为 logo 失败准备文字/色块 fallback。

中文和英文都要测试断行、标点挤压、长标题、超长结果、空字段和窄屏预览。对用户可控文本进行长度限制和清洗；不要通过 `innerHTML` 直接插入原始输入。

### 6. 接入统计并验证

如果项目已接入 `hn-web-analytics`，至少记录 `share_card_open`、`share_card_download`、`share_card_native` 和 `share_link_copy`，字段只发送稳定的 `result_id`、`scope`、`format` 等低敏感维度，不发送图片二进制或结果全文。

验证顺序：

1. 构建通过，类型检查/语法检查无新增错误。
2. 结果级和网站级入口各点击一次，确认弹窗、图片内容和二维码目标正确。
3. 下载前确保下载锚点已挂载到 DOM；验证文件存在、格式为 PNG、尺寸正确且 Object URL 不会过早 revoke。
4. 桌面端验证预览、下载、复制和 Esc/backdrop 关闭。
5. 窄移动端验证不横向溢出、操作按钮可触达、系统分享能力探测和下载 fallback。
6. 用二维码扫描或二维码解码工具检查其 URL；打开后确认结果/语言/筛选状态不丢失。
7. 检查无 CORS、字体加载、Canvas tainted、`navigator.share` 未定义和 clipboard 权限错误。

## 完成标准

- 结果级或网站级入口明确，且卡片内容来自真实数据而非硬编码 demo。
- 卡片包含项目介绍、用户成果、二维码和可读的目标 URL。
- PNG 下载在桌面和移动端可用；支持时系统分享可用，不支持时有明确 fallback。
- 图片生成有 loading/success/error 状态，失败仍能复制链接。
- 公开/私密数据边界清楚，长 query 和个人输入不会泄露到二维码或统计事件。
- 真实浏览器桌面和窄移动端已验证，并说明哪些系统分享能力受浏览器限制。
