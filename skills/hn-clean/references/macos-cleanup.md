# macOS 磁盘分析与清理

## 盘点

用 `df -k` 对同一目标卷做前后快照。用 `du -sk` 测量具体目录的已分配块，按需用 `diskutil` 区分卷、容器和 APFS 快照。只汇总不重叠的路径，并标明单位及统计口径。工具返回部分结果时，报告无法读取的目录和原因。容量仍不足时再扩大扫描范围。

检查本机使用的是 `mole` 还是 `mo`，并以已安装版本的帮助为准。以下命令用于发现候选，执行前核对支持的参数。

```sh
df -k "$HOME"
mole analyze --json "$HOME"
mole clean --dry-run
LC_ALL=C LANG=C mole purge --dry-run
mole installer --dry-run
```

`purge` 侧重旧项目产物，`clean` 侧重缓存等日常项目，`installer` 单独查找安装包。部分版本的 purge 可能受终端区域设置影响，可用命令级 `LC_ALL=C LANG=C` 重试。若 Mole 缺失或无法完成预览，用系统工具继续盘点，并注明覆盖范围。工具默认选中只提供线索。实际运行交互式清理时核对最终选择，取消超出授权范围的所有条目。只有在能限定到已核实条目的情况下，才用批量清理。

## 判断哪些内容可清

- **构建产物和依赖**。检查 Git 跟踪与忽略状态、构建脚本、依赖锁文件和重建所需的源码或环境。`dist`、`node_modules`、`.venv` 和 `.next` 的目录名只能作为线索。用于线上部署、预览或独有运行环境的目录要先查当前用途。
- **应用缓存和安装包**。通过路径、类型、时间及应用状态判断是否为下载缓存或已用过的安装包。普通 ZIP 可能是离线备份或用户资料。优先用应用支持的缓存管理方式处理应用数据，保留聊天、个人资料及同步目录。界面或隐私权限受限时，说明剩余项和可用入口，继续其他条目。
- **大日志**。确认写入者和服务状态。需要保留历史时，验证压缩归档解压后的哈希与源一致，并复查源是否继续增长，再按服务支持的方式轮转或清理。持续增长的日志可在用户要求修复时配置日志轮转，使用服务自身支持的机制或平台的日志管理工具。
- **Docker**。分别查看构建缓存、镜像、容器、卷和宿主机磁盘映像。检查引用关系后处理授权的闲置项。独有本地镜像如果需要保留，先导出并验证可恢复性。避免把卷或容器纳入广泛的 prune，也避免为测量磁盘而启动已停止的 Docker。
- **重复和归档**。先按大小分组，再计算 SHA-256。要保留原路径时，同一 APFS 卷可考虑克隆。核验目标内容、独立写入语义及需要保留的元数据，如权限、时间和扩展属性。打包旧目录时，按需核验权限和符号链接。将归档占用计入净收益。收益很小时可以直接保留。

执行时按已核对的具体路径操作。结合 `lsof`、进程信息、项目锁或应用状态判断使用情况。结果有不确定性时先缩小范围，保留仍可能被使用的内容。保留文件的完整性验证按风险选取 Git 状态、清单或哈希。
