# 会话与闲置项目

## 历史会话

- 用应用提供的会话列表、归档和删除能力。Codex 桌面有对应的会话工具时优先使用。按最后活动时间和项目归组，年龄阈值按用户要求解释，缺失的活动时间标为未知。半年可作为人工审阅的候选阈值。
- 项目、会话、附件和应用缓存分别判断。确认提示词、关键结论、录屏、截图和唯一作品已保存在用户认可的位置，再处理已结束的会话。清理前核实归档是隐藏会话、可恢复导出还是确实释放本地空间。应用缺少受支持的永久删除功能时，记录限制，保留应用数据库与索引。
- 清理记录只保留判断所需的会话标识、时间、路径、大小和去向。项目清理的授权不自动涵盖应用中的关联会话。

## 闲置项目与整库移除

1. 结合最后提交、可取得的实际活动、当前进程和本地修改判断是否闲置。目录修改时间可作线索。
2. 在删除前检查 `git status`、本地分支、stash、worktree、子模块及未提交、未跟踪和忽略文件。重点识别本地原件、必要配置和未推送提交。把共享目录、外部工作树和关联应用数据留在各自的授权范围内。
3. 用户希望保留项目时，验证远端可恢复或备份能覆盖所需内容。配置了远端只表明存在地址。通过远端实际提交核对同步结果，对关键大文件核对可取回的对象或哈希。需要单独归档的本地数据应先确认存储位置，凭据及私密资料按适合的方式保留。
4. 用户明确要求彻底删除并授权丢弃本地独有数据时，按授权删除，并在报告里记录实际范围。若发现用户未预期且会影响范围的独有内容，保留该内容并指出具体影响，等待澄清。
5. 用户明确要求“同步、发布、删除本地”时，先处理分支差异并完成远端同步。通过现有发布流程部署核实过的提交，核验发布版本和关键功能可用。同步或发布所需的验证尚未完成时保留本地项目。满足约定后再移除目标目录，核验路径状态并记录可用的恢复来源。
