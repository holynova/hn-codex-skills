# Hospital Record Collector

Use this skill when the user asks to获取、保存、整理或批量截图岳阳医院微信服务中的电子发票、电子病历，或同时获取两类资料。这里的“下载”默认指将清晰截图保存到本地；遵循用户已经确认的做法，不点击网站的“下载票据”按钮。

## 开始前：用户准备和必要询问

在进行任何微信界面操作前，先用一条简洁消息要求用户：

- 打开微信并完成登录，停留在可操作页面；不要把密码、验证码或医保密码发给助手。
- 指定获取“电子发票”“电子病历”还是“两者”。
- 指定明确的起止日期，例如 `2026-08-01 至 2026-08-31`。如果只说“8月份”，在年份不明确时先询问年份；年份明确时，向用户复述解析后的范围。
- 指定保存文件夹的路径。优先使用绝对路径；相对路径必须先说明将如何解析。如果目录不存在，先询问是否创建，不能默默改存到别处。
- 如果微信中有多个就诊人，询问本次要采集哪一位；不要擅自切换患者。

用户确认微信已登录、范围和目录后再开始。用户未准备好时只等待，不尝试代填登录信息或验证码。

## 微信操作

所有桌面和微信界面操作使用 Computer Use 的 `node_repl` 与 `@oai/sky`：初始化 `sky`，并在首次操作前、每次操作后重新调用 `sky.get_app_state({app: "WeChat"})`。AX 信息不完整时以最新截图判断界面，不复用过期的元素索引或坐标。

按可见界面进入医院服务：

1. 微信搜索“岳阳医院”。
2. 进入医院服务中的“个人中心”；如果当前已经在医院服务页面，则复用当前会话。
3. 进入“互联网服务”。
4. 选择“电子票据”或“电子病历”，取决于用户在准备阶段指定的类型。

进入列表后设置或核对时间范围和院区筛选。若页面只有“近三十天”等预设范围，要逐条核对日期，只保存落在用户指定范围内的记录。对每个日期完整浏览：同一天可能有多张票据或多份病历，必须展开日期、逐条打开每个条目，不能只处理当天第一条。

## 方案1截图和保存

对每一张发票或每一份病历详情：

1. 发票进入“查看详情”；病历打开列表中的病历卡片。
2. 等待详情内容稳定，将微信窗口最大化后重新获取截图。使用截图中的实际文档边界，不把浏览器/微信标题栏、网页标题、底部操作按钮带入结果。
3. 直接保存截图；不要点击“下载票据”“发送到邮箱”或详情中的票据/病历图片。不要把资料上传、发送或分享给第三方。
4. 截图原始文件可暂存于临时目录，再用本地裁切工具（例如 `sips`）生成真正的 PNG 到目标目录。若详情超过一个视口，继续截图并保存全部页面，或按连续分段保存，不能因为只截一屏而遗漏内容。
5. 每保存一份就记录日期、类型、目标路径和是否成功，避免因同日多条记录而覆盖文件。

### 文件命名

- 发票：`YYYY-MM-DD-总金额XX.XX元-发票.png`；同一天多张时追加 `-1`、`-2` 等序号，例如 `2026-08-31-总金额161.00元-发票-1.png`。
- 病历：`YYYY-MM-DD-病历.png`；同一天多份时追加 `-1`、`-2` 等序号，例如 `2026-08-31-病历-1.png`。

发票金额必须读取票据上的“合计”或“价税合计”，不能用支付时间、支付金额或页面列表金额代替。金额看不清时不得猜测；使用 `总金额待确认` 的临时命名并在结果中明确标记，或暂停该条目等待用户处理。已有同名文件时不覆盖，追加序号并报告。

## 完成校验和汇报

完成后用本地命令核对目标目录中的文件存在、格式和尺寸，例如 `file` 与 `sips -g pixelWidth -g pixelHeight`；抽查或逐张查看截图，确认只含发票/病历本体且没有标题栏和底部按钮。将实际日期、发票数量、病历数量、未处理日期或失败原因汇报给用户，并提供目标目录和文件链接。

不要把“列表已浏览”当成“全部已保存”：最终数量必须与逐日、逐条核对结果一致。遇到登录失效、服务查询失败或详情打不开时，有限次数重试；仍失败就保留已完成文件并明确报告未完成项，不编造结果。
